# Edit pass

An edit pass consists of the following tasks and must be conducted by a professional editor:

* Follow the [Microsoft Writing Style Guide](https://docs.microsoft.com/en-us/style-guide/welcome/).
* Ensure correct punctuation, capitalization, spelling, and grammar.
* Ensure that text and graphics/exhibits conform to WWL Exam Writing Style Guide (this document), Microsoft’s Style Guide, and product guidelines as appropriate.
* Ensure consistent and appropriate use of lead-in sentences, standard wording, and boilerplate text.
* Ensure parallelism in lists and answer choices as appropriate.
* Verify use of Microsoft product names and approved people names, company names, and URLs.
* Flag unclear wording or inconsistent terminology, and notify content development vendor CDM of issues.
* Verify use of email addresses and IP addresses.
* Query writer to clarify unclear wording; suggest changes and incorporate writer's revisions as appropriate.
* Ensure consistent tone and style; suggest changes and incorporate writer's revisions as appropriate.
* Ensure consistent terminology as appropriate.
* Ensure descriptors with all product or feature names, UI elements, and key words as appropriate.
* Ensure that exam style sheet is up to date.
* Evaluate item organization and structure; suggest changes and rewrite as necessary.
* Ensure that third-party references follow CELA guidelines.
* Check graphics and screen shots for consistency with associated items, standardization, captioning, and accessibility (font, color, size).
* Check layout of items for formatting or typographic anomalies.
* Identify and resolve localization issues as appropriate.
* Evaluate how material is presented (e.g., list or table vs. paragraph text); suggest changes and rewrite as necessary.
* Ensure consistency across exam or group of exams.

# Exam style sheets

The purpose of an exam style sheet is to document style conventions specific to an exam. It is not necessary to include style decisions that are already specified in this style guide or [Microsoft Writing Style Guide](https://docs.microsoft.com/en-us/style-guide/welcome/).

A style sheet can be used across multiple exams in a portfolio, and exam-specific sections can be added to it if necessary. The exam OD can be used to start or augment your style sheet. In addition, the editor is responsible for verifying whether there is a style sheet for an exam or a related exam. The exam style sheet template and completed style sheets are available in the Edit Resources folder on the Vendor SharePoint site. The editor is also responsible for updating and maintaining the exam style sheet throughout the development cycle. The vendor should send a copy of the style sheet to the Microsoft exam team along with the status mail during the course of content development.

Information that might be on an exam style sheet include the following:

* Definitions of acronyms and guidelines for defining the acronym in each item
* Terms to use and to avoid (e.g., using folder rather than directory)
* Capitalization and spelling of unusual or unfamiliar terms
* Any other information that would be helpful (e.g., lists of built-in groups, suggested names for servers and computers, actual interface labels)

# Acronyms and abbreviations

Use the form of a term that examinees for a specific exam are likely to know best. When in doubt, query the item writers to decide which form will be most recognizable and most fair to examinees. Treat each term consistently throughout a single exam.

Include the spelled-out term, the acronym, and instructions for use in the style sheet for the exam.

Acronyms that do not need to be spelled out for a particular exam should be noted on the exam style guide.

**Rules of first mention** **for acronyms in an item**

* If a spelled-out term plus the acronym in parentheses appears in the stem, only the acronym should appear in the answer choices.
* If the acronym appears for the first time in an answer choice, use the spelled-out term plus the acronym in parentheses in each answer choice in which the acronym appears. Do not use the spelled-out term plus the acronym in parentheses in one answer choice and the acronym only in another.
* If the first mention of the term is a plural noun, include an *s* after the acronym in parentheses, for example, *organizational units (OUs)*.
* If the first mention of the acronym is in a table or graphic, it is not necessary to spell it out. If a subsequent mention is in text, spell it out in the text instead.

## Common wording in answer choices

Be sure to eliminate all unnecessary redundancy from the answer list. If you discover that all answer choices for an item contain identical wording, delete the repetitions. Move the redundant information to the item scenario or the question sentence.

**Incorrect**

Where is your file?

1. It is saved in the WinXP folder.
2. It is saved in the MSOffice folder.
3. It is saved in the Program Files folder.
4. It is saved in the My Documents folder.

**Correct**

In which folder is your file saved?

1. WinXP
2. MSOffice
3. Program Files
4. My Documents

## Correct answers and distractors

### Correct answers must be unquestionably correct to an examinee who has the skill that is being measured.

### Distractors should be plausible to an examinee who does not have the skill that is being measured but should be unquestionably incorrect to an examinee who does have the skill. Distractors must not be fake or made up; they cannot reference technology, features, functionality, or code that does not exist.

## Exclusivity in answer choices

The correct answer and the distractors must be mutually exclusive—that is, there must be no overlap between them. An answer choice that is contained in a longer answer choice is referred to as a subset of that longer answer choice. Neither a correct answer nor a distractor can consist of "all of the above," "none of the above," or "both A and B." This guideline applies both to the quoted phrases ("all of the above," etc.) and to the concepts implied by these phrases.

**Incorrect**

How should you turn on revision marks?

1. Click the **Hide Marks** button.
2. Right-click the affected text.
3. Click **Track Changes** on the Tools menu.
4. Click **Track Changes** on the Tools menu and select **Track changes while editing**.

The correct answer is D, but answer choice C is an incomplete version of this answer. Therefore, C and D are not mutually exclusive, and C is not completely and unquestionably incorrect. Because such overlap and ambiguity can cause confusion among examinees, we must ensure that it does not occur.

**Correct**

How should you turn on revision marks?

1. Click the **Hide Marks** button.
2. Right-click the affected text.
3. Click **Options** on the Tools menu and select **Hidden text** on the View tab.
4. Click **Track Changes** on the Tools menu and select **Track changes while editing**.

## Paths and steps in answer choices

Avoid answer choices that test a candidate’s ability to memorize paths and steps. In most cases, answer choices should use general language to describe the action(s) required to accomplish a task.

**Incorrect**

Create a User: Open Active Directory Users and Computers. Open the Users OU and highlight the Sales OU – File - New UserCorrect

**Correct**

Create a new user in the Sales organizational unit (OU) and use user1 as the account name.

## Fragments vs. full sentences in answer choices

The answer choices for each exam item must be formatted consistently. The answer choices for each item should consist either entirely of sentence fragments or entirely of complete sentences. Do not mix sentence fragments and complete sentences in a single item.

* Sentence fragments should begin with a lowercase letter (unless the term is case-sensitive) and should not use any closing punctuation.
* Complete sentences should begin with a capital letter and end with a period.

# Grammatical Structure of Answer Choices

Be sure that each answer choice responds appropriately to the grammatical structure or syntax of the question sentence.

**Incorrect**

You need to insert a special character into a Word document as quickly as possible. What should you do?

1. changing fonts
2. shortcut keys
3. by typing ASCII characters
4. Use the **Symbol** dialog box.

The question sentence asks for an action, so the correct answer must present an action. The syntax of the question sentence suggests that this action will be presented in imperative form.

However, answer choices A through C do not reflect the syntax of the question sentence. Only answer D provides a logical response to the question. Therefore, all of the answers should be revised to parallel the syntax of D. (The correct answer is B.)

**Correct**

You need to insert a special character into a Word document as quickly as possible. What should you do?

1. Change fonts.
2. Use shortcut keys.
3. Type ASCII characters.
4. Use the **Symbol** dialog box.

# Inappropriate cueing in answer choices

Exam items should test the skill that is being measured, rather than testing reading comprehension or puzzle-solving abilities. Take care not to inadvertently provide cues or clues that will give away the correct answer to an unqualified candidate.

One easy and avoidable trap is to use a word prominently in both the item scenario and the correct answer but not in the distractors. In such a situation, an unqualified candidate can guess the correct answer without possessing any mastery of the material being tested. To correct this problem, you can either eliminate the repeated word or use it in at least one of the distractors, as well as in the correct answer.

**Incorrect**

You need to store the shortcuts to your favorite files and folders. Which folder should you use?

1. WinXP
2. MSOffice
3. Favorites
4. My Documents

The word "favorite" is a giveaway that C is the correct answer.

**Correct**

You need to store shortcuts to the files and folders that you use most often. Which folder should you use?

1. WinXP
2. MSOffice
3. Favorites
4. My Documents

# Number and order of answer choices

### Number of answer choices

Every item must offer a minimum of three answer choices. No maximum has been defined, but for reasons of usability it seems advisable to limit the answer list to about six choices.

The minimum number of answer choices is decided by the following rules:

1. Every single-alphabetic item must offer at least three answer choices - one correct answer and two distractors.
2. Every "Choose *n*" item must offer at least two distractors in addition to the correct answers. (A "Choose *n*" item is a multiple-alphabetic item that specifies the number of correct answers, which in practice will range from two to four.) Thus a "Choose two" item will offer at least four answer choices - two correct answers and two distractors. A "Choose three" item will offer at least five answer choices - three correct answers and two distractors.

Do not use “choose all that apply” item types.

### Order of answer choices

In general, list answer choices in some logical order (such as related pairs together, shortest to longest, or in numerical order if the answers are numbers). If two or more answer choices are worded similarly, they should appear one after another, in order by length. These guidelines are particularly useful for pre-alpha editing, as they can allow for a more efficient alpha review of items; implementation of these guidelines post alpha is at the editor's discretion.

When answer choices are numerical or need to be presented in a specific order for readability (similar answer choices grouped together), answer choice randomization should be disabled.

## Parallel form of answer choices

The correct answer and the distractors should be parallel in form and content whenever possible. In this context, parallelism suggests the following guidelines:

* Similar in length and detail
* Using parallel phrasing
* Representing comparable technical levels

It is acceptable to have answer choices that are not parallel as long as the answers are deemed to be real world and compelling. If it is not feasible to enforce parallelism in a given situation, try to put at least one distractor in the same form as that used for the correct answer to ensure that the correct answer does not stand out. Correspondingly, the two remaining distractors in such an item ought to be parallel, if possible.

## Explanations in answer choices

Exam items should test the skill that is being measured and not teach a candidate possible reasons for taking an action. Therefore, do not include explanations for the actions that appear in answer choices.

## Numbers in answer choices

Answer choices that are numbers, include numbers at the start of the answers, or include numbers in answers should remain in numerical order. Answers should not be randomized.

# Contractions

Do not use contractions in exams. Contractions create localization problems and may hide *not* words. Always spell out words such as *cannot* and *do not*.

# Department names

Use lowercase for department names, such as sales department and human resources department.

# Document conventions

Typographic conventions used in an exam should follow the conventions used in the product and the product documentation as closely as possible. If product documentation is inconclusive or inconsistent, follow the guidelines in the [Microsoft Writing Style Guide](https://docs.microsoft.com/en-us/style-guide/welcome/).

# File names

Whenever possible, label a file name as a file and use a description rather than a file extension to refer to a type of file.

**Incorrect**

Open MyWork.doc.
Run the .exe file.

**Correct**

Open the MyWork.doc file.
Run the executable file.

## Microsoft product Nnmes

### When to Include "Microsoft"

Include "Microsoft" with each full product name in the following circumstances:

* On first occurrence of each product in the exam title.
* On first occurrence of each product name in each item. For case study exams, use on first occurrence of each product name per case study. If a product name has been used in the case, do not use "Microsoft" in the item.

Exceptions:

* See [brand guidance](https://microsoft.sharepoint.com/teams/BrandCentral/Guidelines/Microsoft_Brand-led_Offerings_Guidelines.pdf) to be sure that “Microsoft” references are used appropriately.
* Omit wherever "Microsoft" already appears with the offering or product names in the exam title or in subsequent mentions of the offering or product names.
* Use after first occurrence per item wherever necessary for parallel construction. For example, if answer A were "Microsoft Project," answer B were "Microsoft Excel," and answer C were "PowerPoint," answer C should be changed to "Microsoft PowerPoint" so that the answers would appear to be of equal importance.
* For a series of product names or of multiple versions of the same product that need to include “Microsoft”, include "Microsoft" on the first mention only, for example, Microsoft PowerPoint 2010 and Excel 2010.

### Additional Information

* For exams, in some cases it is acceptable to use product names as modifiers, as shown in the following examples (note that this is an exception to Microsoft Style Guide):
  + Windows client
  + Exchange Server machine

## General considerations

Globalization is the process of creating content that is useful and comprehensible for all customers, whether they are in different states, regions, or countries. Globalization enables localization. Localization involves several processes: translating text from one language to another, adapting textual references from one culture to another, and modifying other materials (such as diagrams and screen shots) so they can be readily understood by target audiences around the world.

Currently, most Microsoft Certification exams are localized for Chinese, Korean, and Japanese audiences. A few high-profile exams are localized in additional languages.

In addition, the English-language versions of our exams and marketing materials are distributed globally. Thus, many people who speak English as a second language (ESL) will be taking our exams and reading our marketing materials in English.

Editors must ensure that all our exams are written as clearly as possible and are free of any cultural references that might confuse or offend non-U.S. individuals. Our goal is to make our materials lucid and direct so that people with limited English can understand them and localization can be fast, easy, and accurate.

Keep in mind that many aspects of culture that we take for granted in the U.S. are unknown elsewhere. Examples include:

* Zip codes and social security numbers are unique to the U.S.
* Barcodes are not used in some countries.
* Daylight savings time is unknown in many parts of the world.
* The concept of "states" (e.g., California, Virginia) will be unfamiliar to many non-U.S. nationals. Japan, for example, has "prefectures," and Switzerland has "cantons," but neither unit is strictly equivalent to a U.S. state.

How you write English source content can significantly affect the quality of translation. Simplified English is easier for non-native English speakers to understand, and translates better into different languages.

Here are some general guidelines on how to write for translation and help to improve the quality of both human translation and machine translation.

## Simple guidelines

Fortunately, the most fundamental rules are easy to remember:

* Use short, simple sentences that present information succinctly.
* Use correct spelling, capitalization, and punctuation.
* Use precise language.
* Use bulleted lists when possible.
* Provide clear, visual delineations between elements of the problem (background information, question, instructions for answering the question).
* Use a consistent writing style and visual presentation across questions of the same type to aid in pattern recognition for neurodivergent individuals.
* Use the same language that appears in the supporting documentation.
* Avoid redundancy.
* Use active voice.
* Minimize scrolling as much as possible.

Here are more detailed guidelines for writing content that's easy to translate into other languages (that is, 'globalized' English):

* Split long sentences into several shorter sentences whenever it's logically possible.
  + Split compound sentences into two or more simple sentences.
  + Make a 'which' clause its own sentence.
  + For long instructions, consider restructuring the content into a bulleted list.
  + Short sentences should be typically about 15-20 words.
* Use standard English word order:
  + Subject + Verb + Object
  + Avoid inverting the subject and the verb (for example, 'Never have I...', 'No sooner had they...', and 'Not only did they...').
  + Use simple verb tenses (simple present, simple past, and simple future).
  + Avoid the use of progressive verb tenses ('am/is/are', 'was/were', 'will be').
  + Avoid the use of perfect verb tenses ('have/has', 'had', 'will have').
  + Don't use a weak 'to be' verb when you can use a stronger verb.
  + Example: 'Work will be finished' should be 'Work will finish'.
* Use active voice instead of passive voice.
  + Example: 'Work was completed' should be 'The team completed the work'.
  + Exception: It's fine to use passive voice to avoid assigning blame to a user, or when the actor is unknown or immaterial.
* Use commas correctly.
* Use semicolons sparingly. It's usually better to create two sentences.
* Don't use - or / as punctuation. For example:
  + "Run the app and verify you can create/edit/display the page." should be written as "Run the app and verify you can create, edit, and display the page."
  + "Run the app - verify you can create a page." should be written as "Run the app and verify you can create a page."
* Avoid parenthetical clauses.
* Use abbreviations or acronyms sparingly.
* Use words and phrases consistently.
* Don't use nominalizations.
  + For example, 'The rapid increase in incident tickets is becoming a concern' should be 'Incident tickets are rapidly increasing and becoming a concern'.
* Avoid noun stacks.
  + For example, 'Install the incident tickets monitoring app' should be 'Install the app to monitor incident tickets'.
* Avoid stacking prepositional phrases on top of one another.
  + Examples of prepositional phrases are [here](http://www.advanced-english-grammar.com/list-of-prepositional-phrases.html).
* Avoid wordiness and jargon, such as English clichés and slang.
  + Technical prose translates better than marketing-style language, jokes, or wordplay.
* Include all words that will clarify a sentence.
  + Include *that* and *who*. They help to clarify the sentence structure. For example, "Select the check box of each folder *that* you want to sync with your desktop."
  + Don't omit articles and other little words from parallel structures.
* Don't use possessives for product or feature names.
  + For example, don't use 'Azure's' or 'Spell Checker's'. 'Azure's security features include' should be 'The security features of Azure include'.
* Don't append s to make types/APIs plural.

## Parts of speech

When editing exams, adhere to the following guidelines:

### Nouns

* **Avoid over-modified nouns.** Translating tools and ESL candidates may have difficulty understanding which qualifier applies to which object if several adjectives are used.
* **Avoid dropped or inappropriately used articles.** Translating tools and ESL candidates will have difficulty understanding a sentence with too many articles missing or used inappropriately.
* **Avoid making nouns into verbs and verbs into nouns (e.g., "to impact", "the troubleshooting").** These constructions are often difficult for a non-native speaker to understand.
* **Include implied pronouns.** Use pronouns before verbs even if they can be implied.

### Verbs

* **Use active rather than passive voice.** Use the format agent/action/object to simplify your sentences when possible. Use the passive voice if it avoids attributing personal characteristics to either software or hardware.
* **Do not omit verbs and auxiliaries.** Omissions make the meaning harder to understand and harder to localize.
* **Avoid dangling participles.** Keep the participle with the verb to make the sentence more comprehensible to a non-native speaker or a localizer.
* **Use "'s" only for possessives.** Do not use contractions such as "the user's" for “the user is”.
* **Avoid making verbs into nouns and nouns into verbs.** These constructions are often difficult for a non-native speaker to understand.

## Sentence structure

* **Use clear, simple, direct sentences.** Avoid compound and complex sentences. Break up long sentences filled with many ideas into short sentences, each expressing one main idea. As appropriate, use bulleted or numbered lists.
* **Use unambiguous word order.** When several different arrangements are possible, choose the one that will lead to the fewest ambiguities.
* **Avoid implied subordination; make all syntactic relations explicit.** For example, the sentence "You repair the hardware the user had problems with" features very complex syntax, including implied subordination, even though it is short and uses simple vocabulary. Rewrite the sentence along these lines: "You repair the hardware that caused problems for the user."
* **Avoid stacks of modifiers.** If possible, use no more than two modifiers per noun. For example, the sentence "Create a content download job schedule" will baffle many readers. Even though "content" and "download" can function as both nouns and verbs, the string "content download job" is actually an adjective phrase that modifies the noun "schedule." This sentence can be rewritten, "Create a schedule for content downloads" or "Create a schedule of jobs to download content."
* **Avoid lists of product names in the middle of other text that will be localized.** In many countries, these product names will remain in English, and long strings of foreign words will cause anxiety for examinees and impede their progress.

## Vocabulary

* **Avoid country-specific names, measurements, and examples.** If you need to use country-specific concepts, try to include a variety of countries in your examples. For instance, you can use dollars in one example and yen in another, or you can use the name Franz in one example and Maria in the next. When you use U.S. units of distance, weight, and measurement, provide a metric conversion for each unit (e.g., 2 miles/4.8 kilometers). For a metric conversion table, either consult <http://www.metric-conversion-tables.com/> or look in the dictionary under "weights & measures."
* **Think about a diverse audience.** For example, a Japanese vendor pointed out that the focus of a Microsoft Access item was first- and last-name columns; however, in Japan the family name is listed first, while the personal name is listed last--the reverse of the system used in the West.
* **Avoid idiomatic expressions.** If a word is used in an idiom, it can be misunderstood or translated in more than one way (e.g.,"lemon" can mean both "an unsatisfactory or defective item" and "a citrus fruit"). In such cases, substitute a more precise expression.
* **Use the same term for the same concept every time it appears.** Otherwise, the localizer will have to check to see whether the different instances need to be translated differently, or whether they actually express the same idea each time.
* **Avoid technical jargon in general text.** Technical terminology is needed to accurately describe product attributes, programmatic procedures, or other technical concepts. But we need to avoid jargon in any context where its meaning can be misunderstood.
* **Use technical terms only in technical explanations.** Technical terms used in technical contexts usually have only one meaning that is easy to understand and localize.
* **Spell out acronyms, abbreviations, and initials consistently.** Always provide the spelled-out versions for accurate translation. Use the style sheet for your exam to define acronyms for localizers.
* **Use short sentences.** Shorter sentences are easier to understand and easier to reproduce in a foreign language.

## Question sentences used most often

All exam items include a question sentence. Question sentences usually take one of the following forms.

* What should you do?
* What should you do?
* What should you do?
* Which *n* actions should you perform? Each correct answer presents part of the solution.
* Which *n* actions should you perform? Each correct answer presents a complete solution.
* Which *n* actions should you perform? Each correct answer presents part of the solution.
* What are *n* possible ways to achieve this goal? Each correct answer presents part of the solution.
* What are *n* possible ways to achieve this goal? Each correct answer presents a complete solution.
* Which *xxx* should you use?
* What should you recommend?

## Interrogative words

Use an interrogative pronoun or adjective to begin the question sentence, such as *which and what*. Typical question types are:

* Which application should you use?
* What should you do next?

The only exception to beginning the question sentence with an interrogative word is made for better placement of a preposition.

**Incorrect**

When you open the file, which document name is displayed?
Which folder should you file the document in?

**Correct**

Which document name is displayed when you open the file?
In which folder should you file the document?

## Negative words

Do not include a negative construction in an answer without approval by Microsoft. A negative construction in an answer is never permissible if there is a negative construction in the stem.

Avoid a negative construction in a question statement unless the candidate really needs to know when not to do something, in which case, cap and boldface the negative word.

There are several ways to turn a negative question into a positive one. In multiple-alphabetic items, simply reverse the question and find out which distractor then becomes the correct answer. For example, if the correct answers to "Which methods do not return the required results?" are A, C, and D, you might be able to change the question to "Which method returns the required results?" with the correct answer being B.

You might also be able to reword the question, such as "Which methods fail to return the required results?"

You can also completely recast the question. Instead of asking, "Which statements do not return the desired results?", use a scenario in which the wrong statement is used, and then ask "What happens next?" The correct answer might be "The program returns an error message."

## Question Paragraph

This paragraph contains the question and sometimes an instruction statement or statements, such as "Each correct answer presents part of the solution."

## Telegraphing answers

The question sentence should telegraph the correct answer, that is, a knowledgeable examinee should be able to formulate the answer before reading the choices.

**Incorrect**

What should you do with the XYZ utility?
(There might be a myriad of uses for the XYZ utility.)

**Correct**

How should you use the XYZ utility to find files quickly?

## True/False statements

Avoid questions of the type "Which statement about xyz is true?" or "Which statement about xyz is false?" These items telegraph answers poorly.

## What vs. which

Use *what* in a question sentence to stand alone as an interrogative pronoun; use *which* as an adjectival interrogative pronoun.

**Examples**

What should you do?
What should you recommend?
Which software should you install on the Windows 7 client?
Which encryption method should you recommend?

Your solution must meet the following requirements:
You need to recommend a solution that meets the following requirements:

You must meet the following requirements:

## Security Quick Tips

It is important to be mindful of the following principles when making public statements (written or oral) about the security, safety, or privacy features or policies of Microsoft products and services:

* Add "helps" as in "helps protect..."
* Absolute "security, safety, protection, and privacy" don't exist.  Don't overstate.
  + Don't Say: "With MSN your personal information is protected."
  + Do Say: "MSN uses innovative security technologies to help protect your personal information."
  + Don't Say: "MSN Wallet provides a secure way to shop online."
  + Do Say: "MSN helps keep your purchase information confidential with the security technologies employed by MSN Wallet."
* State security "technologies," "features," and "enhancements" without making absolute promises.
  + Dont Say: "Ensure your children's safety and enjoyment online."
  + Do Say: "MSN Online Safety features give you the tools you need to help protect your  kids online."
* Avoid indirect comparisons.
* Avoid "safer" and "more secure"
* Implied comparisons require broader substantiation.
  + Don't Say: "MSN Parental Controls are better." (Better than what?)
  + Do Say: "MSN Parental Controls keep you informed of your child's online activities."

# Teaching text

## Exam items should test the skill that is being measured, not teach a candidate something about that skill. Therefore, do not include explanations in any text.

**Example**

The traffic from users who access a static web page should be spread across three servers.
You need to configure DNS to support this configuration.
What should you do?
Implement round robin by creating three identical A records, each pointing to the static page on each server.

Inclusion of “Implement round robin” teaches the candidate what round robin is.

# Terminology

To assist with localization and comprehension, use the same words to refer to the same things throughout the exam. That is, do not refer to the Xyz executable file one place and the Xyz.exe file another. Similarly, avoid using the same word to express different meanings. For example, do not use the word “site” within an exam to refer to a physical location, a logical location, and a Web address.

The item writer should identify each term by type. Many terms are formatted or used differently depending on the context. When an item says, "Use Print," do we mean the **Print** command, **Print** method, **Print** dialog box, or *print* table?

# Verb tenses

Use present tense as much as possible while preserving clarity, logical, and temporal sequence. Instead of asking, "What will happen when you open the file?", ask, "What happens when you open the file?" Especially avoid complex tenses such as past perfect and future imperfect. Complex tenses are difficult to localize accurately.

See also the guidelines in the “Best Practices for Developer Exams” document and the Item Writer Training slide deck, both available in the CDM Resources folder on the Vendor site.

# Version numbers

Do not specify the version number of a product unless it is important to contrast current and previous versions or for reasons of clarity and technical accuracy.

Do not precede the version number with the word *version* in the first mention or in subsequent mentions.

**Incorrect**

If you are using Microsoft SQL Server 2008 version 10.50.1765.0 or later … (first mention)
If you are using Internet Explorer version 8.0 or later … (first mention)

**Correct**

If you are using Microsoft SQL Server 2008 10.50.1765.0 or later … (first and all mentions)
If you are using Microsoft Internet Explorer 8.0 or later… (first mention)

# Application vs. program

(*Exception to MSTP*) Use *application* when referring to a stand-alone product that helps users accomplish a particular kind of work, such as word processing or database management, as opposed to an *operating system* (which runs a computer), a *utility* (which performs maintenance or general-purpose chores), or a *language* (with which computer programs are created). Microsoft Excel, Microsoft Word, and Microsoft Access are all considered to be applications.

Use *program* when referring to a set of instructions that tells a computer what to do, such as a setup program.

**Examples**

* The sales department needs to run both 16-bit and 32-bit Windows-based applications.
* Run the Windows Server 2008 Setup program.

# Named vs. called

Use *named*, not *called*, when referring to the specific names of things.

**Incorrect**

Two domains called Sales and Marketing

**Correct**

Two domains named Sales and Marketing

# Can, should, must, might

In certification exams, these auxiliary verbs have very specific meanings:

Use *should* in question sentences to mean that the action or result is the best solution for a given problem.

Do not use *should* to state requirements or to indicate probability.

Avoid using *can, must, might, do, would,* or *may* in **question sentences**.

**Examples**

* Which two actions should you perform?
* What should you do?

# Report vs. complain

Do not use *complain* in an exam item. Instead, use *report* when referring to feedback from users.

# Determine

*Determine* has multiple meanings in English and can therefore be ambiguous and hard to translate. Do we mean "find out what has already been set" or "set something yourself"? Use *verify, clarify, identify, set, discover, establish, calculate*, or *decide*.

# Domain

In general, use title caps for domain names, but consult product documentation to verify.

# In order for, in order that

Avoid; use *so that* instead.

# Join

*Join* can be used as a verb when referring to computers, as in "Any computer can join any single workgroup."

# Location vs. site

In networking terminology, *location* refers to a physical location and *site* refers to a logical location. Do not use the terms interchangeably.

# May

Do not use *may* in certification exams; *may* has multiple meanings in English and is therefore ambiguous and hard to translate. When referring to what is a valid action, use *can* plus the appropriate verb. When referring to what is within the realm of possibility, use *might* plus the appropriate verb.

# Network adapter

Use *network adapter*, not *adapter card, network adapter card, network interface card,* or *NIC*.

*Network adapter* is usually used in preference to network adapter card because not all network adapters are cards. Some are external, such as those used for portable computers. There might be times when it would be important to note whether the adapter is a card, but there is usually no reason to make this distinction.

# Of the following

Use sparingly when answer choices are not parallel.

Do not use when answer choices are parallel, for example, ask, "Which method should you use?" rather than "Which of the following methods should you use?"

# Only

The adverb *only* should be placed with care to avoid ambiguity. Usually, *only* should be placed as close as possible to the word or words that it limits. Variation in the placement of *only* can change the meaning of the sentence, as the following examples show:

**Examples**

* Only the system administrator can change the password.
  (No one else can change it; *only* is an adjective modifying *system administrator*.)
* The system administrator can only change the password.
  (The system administrator can do nothing else; *only* is an adverb modifying *change*.)
* The system administrator can change only the password.
  (The system administrator can change nothing else; *only* is an adjective modifying *password*.)

# Relate

*Relate* also has multiple meanings in English and is therefore ambiguous and hard to translate. Do we mean "show the relationship between" or "tell"?

# Supported

*Supported* can be used as in the following example:

Microsoft Exchange 2010 is *supported* only on Windows Server 2008.

# System

*System* has multiple meanings in English and can therefore be ambiguous and hard to translate. Try substituting a more precise term, such as *computer, network, database, or application.*

# Technical support

Use *technical support* or *technical-support personnel*, not *support, tech support, technical support desk,* or *support desk*. The term *help desk* is okay to use.

Use *technical-support line*, not *hotline*.

# They

Do not use *they* to refer to a single subject. Do not resort to *he/she*. Recast instead.

**Correct**

A user who logs on will … When users log on, they will ...

**Incorrect**

When a user logs on, they will …
When a user logs on, he/she will …

# Up to

"Up to *x*" means "*x* minus 1." For example, if you want to describe a range from 0 to 6, use "as many as 6" rather than "up to 6" because "up to 6" defines a range from 0 to 5.

# Using vs. by using

Do not use ‘using’; see the MSTP entry.

# Using vs. with

Do not use ‘with’ in place of ‘by using’; see the MSTP entry.

# Via

Use to mean *by way of* (in a geographical sense), not *by means of*. It’s acceptable to use to describe electronic routes, as in "via modem."

# What vs. which

Use *what* in the question sentence to stand alone as an interrogative pronoun or with a collective noun such as information. Use *which* as an adjectival interrogative pronoun.

**Examples**

What should you do?
What are two possible ways to achieve this goal?
Which code segment should you use?
Which action or actions should you perform?

# Would

Avoid using *would* in questions, as in "How would you do this?" Just because you would do something does not mean that you should do it. Use *should* instead. Use forms of *would* only when referring to procedures carried out by inanimate objects, not people.

# Would like

*Would like* has emotional connotations that are inappropriate in an exam item. Use *want* or *need* instead.
